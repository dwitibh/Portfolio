Migrating Marketing Analytics from Supermetrics to Microsoft Fabric

A two-person data team transformed a fragmented setup of 20-25+ scattered, API-driven marketing reports into a governed medallion architecture on Microsoft Fabric. Delivered in three structured phases, with 30+ Power BI reports migrated and zero data loss.

The Challenge

Why the existing Supermetrics setup was no longer sustainable:

  • 20-25+ scattered reports Different reports connected to different API endpoints, creating a fragmented setup that was difficult to manage.
  • No governance or security No centralised security model or consistent governance across the reporting layer.
  • Impossible to debug Unique filters and date ranges made failures hard to reverse-engineer when issues appeared.
  • Not built to scale As campaigns multiplied and data sources expanded, the architecture became unsustainable.
Phase 1 · Discovery

Laying the Foundation

1
Stakeholder Workshops
Ran focused sessions to understand business goals, reporting gaps, and future priorities.
2
Report Reverse Engineering
Mapped existing reports to uncover logic, dependencies, and hidden duplication across the setup.
3
Supermetrics Consultation
Aligned with Supermetrics engineers on platform constraints, changes, and migration considerations.
4
Schema Deep-Dive
Documented schemas, columns, and endpoint details to define the technical foundation for Azure.

Discovery Outputs

  • Priority matrix of all reports
  • Redundant reports identified
  • Future report pipeline mapped
  • Critical KPIs catalogued
  • API constraints documented
  • Go/no-go criteria established

Documents Managed

Key discovery artefacts kept the migration transparent, collaborative, and easy to validate:

Mapping Doc
Tables, columns, aggregations, and pivots captured in one source of truth, shared with data engineers for full visibility and comment threads.
Business Logic Log
All current report logic captured for cross-checking during migration.
Change Tracker
Timeline, blockers, change requests, and team contributions tracked in one place.
Refresh Plan
Data frequency and load type agreed in a dedicated workshop with stakeholders.
Phase 2 · Build

Architecture & Engineering

Built the medallion architecture in Microsoft Fabric with defined ownership layers, transformation stages, and reporting delivery patterns.

Engineering Decisions

Table Categorisation
Reviewed source tables and grouped them into raw, curated, and reporting-ready sets for cleaner ownership.
Star Schema Design
Designed a reporting-friendly model with clear dimensions, facts, and consistent KPI definitions.
Smart Refresh Strategy
Balanced refresh frequency and query performance to support both Direct Query and Import mode.
Phase 3 · Testing, Validation & Sign-Off

Testing and Validation Strategy

1
Logic Validation
Validated columns, calculations, and business logic against current reports.
2
KPI Number Matching
Tested critical metrics to confirm numerical accuracy across all reports.
3
Parallel Running
Ran old and new reports together for 1-2 weeks to confirm stability.
4
Formal Sign-Off
Secured stakeholder approval before commissioning to production.

Challenges Navigated

  • Schema drift from the API source Upstream changes shifted schemas mid-migration and were caught by the validation layers.
  • Renamed field calls breaking pipelines Traced through the mapping doc and corrected without losing lineage.
  • Social media OAuth authorisation issues Re-established authorisations and hardened the refresh setup. All resolved with zero data loss.
